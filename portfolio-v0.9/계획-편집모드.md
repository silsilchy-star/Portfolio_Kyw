# 편집 모드 (Edit Mode) — 작업 계획서

작성일: 2026-09-11
대상: 포트폴리오 랜딩페이지 v0.6.1
성격: **임시 도구.** 5단계(내용 기입)가 끝나면 통째로 제거한다.

---

## 0. 목적과 전제

내용을 채우려면 `index.html`에서 `TODO` 문구를 찾아 하나씩 고쳐야 합니다.
문구가 100개가 넘고 태그 사이에 흩어져 있어, 코드에서 찾는 것보다
**페이지에서 눈으로 보면서 고치는 쪽이 훨씬 빠릅니다.**

이 도구는 그 한 가지만 합니다. 오래 쓸 물건이 아니므로 **제거가 쉬운 것**이 최우선입니다.

### 확정 사항

| 항목 | 결정 |
|---|---|
| 편집 범위 | **HTML에 직접 쓰인 텍스트만** |
| 저장 방식 | **완성된 `index.html` 내보내기** (기존 파일과 교체) |
| 배치 | **독립 파일** `edit-mode.js` — `index.html`에 `<script>` 한 줄 |
| 제거 | 그 한 줄을 지우면 끝 |

---

## 1. 제거 가능성을 최우선으로 — 독립 파일 구조

편집 기능을 `app.js`나 `style.css`에 섞으면, 나중에 **어디까지가 편집 도구인지 가려내야 합니다.**
그래서 전부 파일 하나에 담습니다.

```
portfolio/
├── index.html      ← <script src="edit-mode.js"></script> 한 줄만 추가
├── style.css       ← 건드리지 않음
├── app.js          ← 건드리지 않음
└── edit-mode.js    ← 편집 도구 전부 (CSS 포함, JS가 주입)
```

- 편집 도구의 CSS도 `edit-mode.js`가 `<style>` 태그로 직접 주입합니다. `style.css`는 손대지 않습니다.
- **제거 절차**: `index.html`에서 `<script src="edit-mode.js">` 줄 삭제 → `edit-mode.js` 파일 삭제. 끝.
- 내보내기 결과물에는 **이 script 줄이 이미 빠져 있습니다.** 내보낸 파일로 교체하면 제거까지 자동으로 끝납니다.

---

## 2. 편집 대상 — 무엇이 되고 무엇이 안 되는가

페이지의 텍스트는 출처가 두 가지입니다. 이 구분이 이 도구의 핵심 한계입니다.

### ✅ 편집 가능 — `index.html`에 직접 쓰인 텍스트

| 탭 | 대상 |
|---|---|
| 소개 | 로그라인, 서브 카피, 키워드 칩, 자기소개 3문단, 요약 블록 4개, 이력 3건 |
| 프로젝트 | 프로젝트명·설명·태그·지표 라벨·지표 숫자 (3건) |
| 기술 | 도구명·숙련도·설명 (7행) |
| 문서 | 섹션 제목·설명 (서류철 헤더) |
| 이력서 | 로그라인 인용, 본문 4문단, 강점 카드 3장, 케이스 2건의 모든 단계 본문, 포부 3건, 마무리 문장 |
| 공통 | 상단 로고, 푸터, 각 탭 개요 문구 |

### ❌ 편집 불가 — `app.js` 배열에서 생성되는 텍스트

| 구간 | 수정 위치 |
|---|---|
| 문서 서류철 6개 (라벨·제목·요약·태그) | `app.js` → `FILES` |
| 게임 카드 4개 | `app.js` → `GAMES` |
| 궤도 맵 노드 5개 | `app.js` → `ORBIT_DATA` |
| 이력서 단계 라벨 (S/T/A/R/L) | `app.js` → `RESUME_FRAMEWORKS` |
| 사이드 내비 목차 | `index.html`의 `data-anchor-label` 속성 |

**이걸 그냥 두면 함정이 됩니다.** 서류철 카드 글자를 고치고 저장했는데
새로고침하면 원래대로 돌아오는 일이 반드시 생깁니다. `app.js`가 페이지를 열 때마다 다시 그리기 때문입니다.

그래서 **JS 생성 구간은 편집을 막고, 그 자리에 배지를 띄웁니다** — `app.js → FILES` 처럼
어느 배열을 고쳐야 하는지 직접 알려줍니다. 헛수고를 원천 차단하는 것이 목적입니다.

## 3. 화면 구성

편집 모드를 켜기 전에는 **우측 하단 작은 버튼 하나**뿐입니다. 페이지는 평소와 똑같이 동작합니다.

```
┌──────────────────────────────────────────────┐
│                                              │
│   (평소 페이지)                               │
│                                              │
│                                              │
│                          ┌─────────────────┐ │
│                          │ ✏ 편집          │ │ ← 평소엔 이것만
│                          └─────────────────┘ │
└──────────────────────────────────────────────┘
```

편집을 켜면 하단에 막대가 펼쳐집니다.

```
┌──────────────────────────────────────────────┐
│  ┆ 편집 중인 문구에 점선 테두리                │
│  ┆ 클릭 → 그 자리에서 바로 타이핑              │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ ✏ 편집 중   TODO 43   변경 7             │ │
│ │ [HTML 내보내기]  [되돌리기]  [끄기]       │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

| 요소 | 역할 |
|---|---|
| **TODO 43** | 아직 안 고친 `TODO` 문구 개수. 0이 되면 완료 신호 |
| **변경 7** | 이번 세션에서 고친 개수 |
| **HTML 내보내기** | 편집 결과를 `index.html`로 내려받기 |
| **되돌리기** | 마지막 편집 하나 취소 (연속 가능) |
| **끄기** | 편집 종료, 평소 페이지로 복귀 |

## 4. 동작 방식

### 4-1. 편집

- 대상 요소에 `contenteditable="plaintext-only"`를 붙입니다.
  일반 `true`는 붙여넣기할 때 서식과 태그가 딸려 들어와 마크업이 더러워집니다.
  (미지원 브라우저는 `true`로 떨어뜨리고 붙여넣기를 가로채 평문만 넣습니다.)
- `Esc` → 편집 취소하고 원래 값 복귀. `Ctrl/⌘+Z` → 되돌리기.
- 줄바꿈이 필요한 문단은 `Shift+Enter`로 `<br>`을 넣습니다. 그냥 `Enter`는 편집 종료.

### 4-2. 안전장치

| 위험 | 대응 |
|---|---|
| 내보내기 전에 창을 닫음 | 변경분이 있으면 `beforeunload` 경고 |
| 새로고침하면 사라짐 | 막대에 상시 안내 문구 + 변경 개수 표시 |
| JS 생성 구간을 고침 | 편집 차단 + `app.js → 배열명` 배지 |
| 태그를 지워버림 | 편집 단위를 **텍스트가 든 말단 요소**로만 한정. 컨테이너는 대상에서 제외 |

**브라우저 저장소는 쓰지 않습니다.** 로컬 파일(`file://`)에서 여는 페이지라
브라우저마다 `localStorage` 동작이 제각각이고(Safari는 아예 막습니다),
"저장된 줄 알았는데 없다"가 가장 나쁜 실패입니다. 저장 경로를 **내보내기 하나로 단일화**합니다.

### 4-3. 내보내기

문서를 통째로 복제한 뒤, 편집 도구의 흔적을 전부 걷어내고 파일로 만듭니다.

1. `document.documentElement`를 복제
2. 제거 — 편집 막대, 주입한 `<style>`, `<script src="edit-mode.js">`
3. 속성 정리 — `contenteditable`, `spellcheck`, 편집용 `data-*`, 편집용 클래스
4. 런타임 잔여물 원복 — `app.js`가 인라인으로 넣은 값들을 걷어냄
   (풀블리드 `width`/`margin-left`, 궤도 노드 `transform`, 서류철 폴더 좌표,
   리빌 `is-in` 클래스, 사이드 내비에 채워진 링크, JS가 그린 카드들)
   **이걸 안 하면 내보낸 파일에 계산된 좌표가 굳어버려 다른 화면 크기에서 깨집니다.**
5. `<!DOCTYPE html>`을 붙여 `index.html`로 내려받기

### 4-4. 되돌리기

편집 전 값을 스택에 쌓고 `Ctrl/⌘+Z`로 하나씩 꺼냅니다. 최근 50개까지.

## 5. 만들지 않는 것

용도가 임시라 아래는 **의도적으로 넣지 않습니다.**

- 서식 도구(굵게·기울임·색상) — 텍스트 교체가 목적이고, 서식은 `style.css`의 일이라 섞으면 톤이 무너집니다
- 이미지·링크 편집 — 경로는 코드에서 고치는 편이 정확합니다
- 섹션 추가·삭제·순서 변경 — 구조 변경은 HTML에서
- 자동 저장·서버 연동 — 정적 파일 한 장이라는 전제를 깨뜨립니다
- 다국어·버전 관리

## 6. 완료 기준

- [ ] `<script>` 한 줄 추가만으로 동작, 그 줄 삭제만으로 완전 제거
- [ ] `style.css`·`app.js` 무수정
- [ ] HTML 텍스트 전 구간 편집 가능, JS 생성 구간은 차단 + 출처 배지
- [ ] 내보낸 `index.html`을 교체하면 편집 도구 없이 정상 동작
- [ ] 내보낸 파일에 런타임 잔여물(계산된 좌표·인라인 스타일) 없음
- [ ] 변경 후 창을 닫으려 하면 경고
- [ ] 모바일에서도 편집 가능 (막대는 하단 고정, 입력창 16px 이상)
- [ ] 편집 모드를 꺼도 페이지 기능(탭·궤도·서류철)이 모두 정상

## 7. 사용 절차

1. `index.html`과 같은 폴더에 `edit-mode.js`를 둔다
2. `index.html`을 브라우저로 연다
3. 우측 하단 **✏ 편집** 클릭
4. 문구를 클릭해 고친다. **TODO 개수가 0이 될 때까지**
5. **HTML 내보내기** → 내려받은 파일로 기존 `index.html` 교체
6. `edit-mode.js` 삭제 (내보낸 파일에는 이미 연결이 빠져 있다)

## 구현하며 잡은 것

**설치 안내 주석까지 제거** — `<script src="edit-mode.js">` 태그만 지웠더니 그 위의
설치 안내 HTML 주석이 내보낸 파일에 그대로 남았습니다.
"아직 편집 도구가 붙어 있나?" 하고 헷갈릴 여지라, 주석 노드도 함께 걷어내도록 했습니다.

**런타임 잔여물 제거가 핵심** — `app.js`는 실행 중에 상당한 흔적을 남깁니다.
풀블리드 밴드의 계산된 `width`/`margin-left`, 궤도 노드 5개의 `transform`,
서류철 폴더 6개의 좌표, 리빌 `is-in` 클래스, 사이드 내비에 채운 링크, 이력서 단계 기호.
이걸 그대로 내보내면 **계산된 좌표가 파일에 굳어** 다른 화면 크기에서 깨집니다.
내보내기 직전에 전부 원복합니다.

**탭 상태도 원복** — 이력서 탭을 보면서 내보내도 파일은 항상 '소개' 탭이 열린 상태로 나옵니다.

**테마 패널 시험값은 버림** — 패널에서 색을 바꿔본 상태로 내보내도 그 값은 파일에 남기지 않습니다.
영구 적용 경로는 테마 패널의 **CSS 복사** → `style.css` 이며, 두 경로가 섞이면 어느 쪽이 진짜인지 알 수 없어집니다.
