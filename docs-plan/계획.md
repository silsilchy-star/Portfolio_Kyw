## 1. 확정된 설계 결정

### 1-1. 내비게이션 구조 — **하이브리드**
요구사항 문서에 두 방식이 병기되어 있어 아래와 같이 통합한다.

```
┌─────────────────────────────────────────────────┐
│  [로고]   소개 · 프로젝트 · 기술 · 문서 · 게임   │ ← 상단 스티키 탭 (SPA 뷰 전환)
├──────────┬──────────────────────────────────────┤
│ 사이드   │                                      │
│ 내비     │   활성 섹션 본문                     │
│ (소제목  │                                      │
│  앵커)   │   ← 앵커 스무스 스크롤               │
│ sticky   │                                      │
└──────────┴──────────────────────────────────────┘
```

- **대분류 5개**(소개/프로젝트/기술/문서/게임) → 상단 탭으로 **뷰 전환**. 한 번에 하나의 `<section>`만 활성.
- **각 뷰 내부의 소제목** → 좌측 사이드 내비의 앵커 링크로 **스무스 스크롤**.
- URL 해시(`#intro`, `#projects/…`)로 딥링크·뒤로가기 대응.
- 모바일(≤768px): 사이드 내비는 접히고, 상단 탭은 가로 스크롤 칩 형태로 전환.

### 1-2. 편집 GUI — **테마 패널 골격만**
- 우측 슬라이드-인 패널(`#theme-panel`)을 **자리만** 배치.
- 컨트롤 목록(색상 피커 / 폰트 선택 / 텍스트 크기 / 섹션 높이 슬라이더)은 마크업만 존재, 로직은 2단계.
- 모든 심미 값은 `:root` CSS 변수 1곳에 모아둔다 → 패널이 나중에 `style.setProperty()` 한 줄로 제어 가능.

### 1-3. 파일 구조 — **3파일 분리**
```
portfolio/
├── index.html      구조·콘텐츠 슬롯
├── style.css       토큰 + 레이아웃 + 컴포넌트
└── app.js          탭 전환 / 스크롤 / 스파이 / 패널
```

## 3. 디자인 토큰 이식 계획

`DESIGN 1.md`의 Quick Start CSS 블록을 **그대로** `style.css` 최상단 `:root`에 이식한다.
추가로 뼈대 운용용 변수를 얹는다.

```css
:root{
  /* --- DESIGN 1.md 원본 토큰 (색/타이포/스페이싱/라운드/섀도우) --- */
  ...
  /* --- 뼈대 운용 변수 (사용자 조정 대상) --- */
  --nav-height: 56px;
  --sidebar-width: 220px;
  --section-min-height: 100dvh;   /* 페이지 길이 조절 GUI가 제어할 값 */
  --content-max: var(--page-max-width);
  --font-display: var(--font-satoshi);
  --font-body: var(--font-inter);
}
```

**준수 사항 (Do's & Don'ts 반영)**
- 컨테이너 구분은 `1px solid var(--color-ash)` — 그림자 금지
- 본문 색상은 `#171717`, 순수 검정 사용 안 함
- Satoshi는 36px 이상 전용, 그 이하는 Inter
- 라운드는 정의된 5종(9999 / 16 / 12 / 8 / 6px)만 사용
- Electric Blue는 강조용, 큰 면적 배경 금지
- 한 컴포넌트에 액센트 컬러 1개만

**폰트 로딩**: Satoshi는 웹폰트 라이선스 이슈가 있으므로 1단계는 `Inter` + `system-ui` 폴백 스택으로 두고, 한글은 `Pretendard` → `Apple SD Gothic Neo` 순으로 폴백. 2단계에서 사용자가 교체 가능.

# 부록 A. 2단계 "톤 입히기" 작업 기록

## A-1. 변수 4층 구조

기존 1단계는 토큰이 한 층(`:root` 평면)이라 다크모드와 사용자 조작을 동시에 감당할 수 없었습니다.
2단계에서 네 층으로 분리했습니다.

```
[1층] 원자 팔레트    --color-electric-blue: #2563eb        DESIGN 1.md 원본. 이름 변경 금지.
        ↓
[2층] 시맨틱 토큰    --accent: var(--color-electric-blue)  역할 기반 별칭.
                     --bg / --surface / --border / --text   ★ 다크모드는 이 층만 통째로 교체
        ↓
[3층] 사용자 배율    --type-scale / --display-scale         ★ 테마 패널이 조작하는 값
                     --density / --radius-scale
        ↓
[4층] 계산 토큰      --text-display: calc(var(--base-display) * var(--display-scale))
                     --spacing-16: calc(16px * var(--density))
```

**이 구조의 핵심 이점**: 미디어쿼리는 `--base-*`(base 값)만 바꾸고, 사용자는 `--*-scale`(배율)만 바꿉니다.
따라서 사용자가 제목 크기를 키워도 모바일 반응형이 깨지지 않습니다.
(1단계처럼 절대 px를 직접 덮어쓰면 인라인 스타일이 미디어쿼리를 이겨 반응형이 죽습니다.)

## A-2. 다크모드

세 가지 상태를 지원합니다.

| 상태 | 트리거 | CSS 선택자 |
|---|---|---|
| 시스템 | 기본값 | `@media (prefers-color-scheme:dark) { :root:not([data-theme="light"]) }` |
| 라이트 고정 | 패널 선택 | `:root[data-theme="light"]` (기본 `:root` 값 유지) |
| 다크 고정 | 패널 선택 | `:root[data-theme="dark"]` |

`data-theme`은 `<html>`에 붙습니다. 다크 값은 그림자·스크림·도트 그리드까지 별도로 재정의했습니다.

**주의점 하나**: 라이트에서 고른 색상 지정값이 다크에서 그대로 남으면 대비가 깨집니다.
그래서 모드를 바꾸면 색상 계열 지정값(`--accent`, `--bg`, `--text` 등 8종)만 자동으로 비워지고,
크기·간격·폰트 지정값은 유지됩니다. 색상 피커는 새 테마의 실제 값으로 재동기화됩니다.

## A-3. 테마 패널 (전 컨트롤 실동작)

| 그룹 | 컨트롤 | 대상 변수 |
|---|---|---|
| 모드 | 시스템 / 라이트 / 다크 | `data-theme` |
| 프리셋 | 기본 · 먹지 · 한지 · 청록 · 자주 · 심야 | 색상 8종 일괄 |
| 색상 | 액센트, 배경, 영역 배경, 카드 배경, 본문/보조 글자, 테두리, 주 버튼 | `--accent` `--bg` `--bg-alt` `--surface` `--text` `--text-3` `--border` `--action-fill` |
| 타이포 | 제목/본문 폰트, 제목/본문 크기, 본문/제목 굵기 | `--font-display` `--font-body` `--display-scale` `--type-scale` `--weight-body` `--weight-heading` |
| 레이아웃 | 본문 최대 폭, 섹션 간격, **섹션 최소 높이(페이지 길이)**, 밀도, 라운드, 상단바 높이, 사이드 폭 | `--content-max` `--section-gap` `--section-min-height` `--density` `--radius-scale` `--nav-height` `--sidebar-width` |

- **CSS 복사**: 변경한 값만 모아 `:root{ … }` 블록으로 만들어 클립보드에 복사합니다.
  그대로 `style.css` 하단에 붙여넣으면 영구 적용됩니다.
- **초기화**: 인라인 지정값을 전부 제거하고 시스템 모드로 되돌립니다.
- 변경값은 **브라우저 저장소에 남기지 않습니다.** 새로고침하면 초기화되며, 영구 반영은 "CSS 복사" 경유가 유일한 경로입니다.
  (의도된 설계입니다 — 파일이 진실의 원천이고, 패널은 실험 도구입니다.)

## A-4. 비주얼 톤 적용 내역

- **도트 그리드**: 히어로 뒤 22px 간격 radial-gradient + 타원형 mask 페이드. DESIGN 1.md의 시그니처 텍스처.
- **보더 우선 elevation**: 그림자는 히어로 목업의 4px 링과 패널/드로어에만. 카드는 전부 1px 보더.
- **액센트 규율**: 컴포넌트당 1색. `data-accent`가 `--accent-local` 슬롯을 바꾸고, 자식은 그 슬롯만 참조합니다.
- **호버 상태**: 카드 `translateY(-2px)` + 보더 강조, 소개 블록은 좌측 3px 액센트 바가 페이드인.
- **지표 숫자**: 모노스페이스 + `tabular-nums`로 자릿수 정렬.
- **입력 포커스**: 액센트 보더 + `--tint` 3px 링.

# 부록 B. 참고 글 대조 — "AI가 만든 티를 없애는 랜딩페이지 디자인"

출처: <https://brunch.co.kr/@acc9b16b9f0f430/240>

글이 제시한 5단계와 이 프로젝트의 5단계는 거의 같은 뼈대입니다. 대조표:

| 글의 단계 | 글의 처방 | 이 프로젝트에서의 상태 |
|---|---|---|
| 1. 디자인 뼈대 | Get Design MD로 유명 기업 디자인 시스템 확보 | ✅ `DESIGN 1.md`(Dub)가 정확히 그 산출물. 1~2단계에서 토큰 전량 이식 |
| 2. 브랜드 톤 | 눈누에서 무료 한글 폰트 선택 | ⚠️ **2단계에서 빠져 있던 항목** → 아래 B-1에서 보강 |
| 3. 안목 | Dribbble·21st.dev 캡처 2~3장 확보 | ➖ 레퍼런스 없이 진행 선택. `DESIGN 1.md`의 Similar Brands(Linear·Vercel·Cal.com·Raycast) 패턴을 기준으로 대체 |
| 4. AI에 정확히 지시 | 제안 → 승인 → 순차 수정 | ✅ 각 단계 착수 전 선택지를 물어 승인받고 진행하는 방식 유지 |
| 5. 애니메이션 | 스크롤 애니메이션 추가 | ✅ 3단계에서 **절제형**으로 적용 (B-2) |

**가장 중요한 발견**: 글이 말하는 "디자인 뼈대"는 이미 갖췄지만 **"브랜드 톤 = 한글 폰트"가 비어 있었습니다.**
영문 스택(Inter/Satoshi)만 있고 한글은 시스템 폰트 폴백이라, 한글 콘텐츠가 들어가는 순간 톤이 무너질 상태였습니다.

## B-1. 한글 폰트 적용 (2단계 보강)

**Pretendard Variable 단일 서체**로 통일했습니다. (SIL OFL, 상업적 이용 가능)

```html
<link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin>
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css">
```

- `dynamic-subset`은 페이지에 실제로 쓰인 글자만 내려받으므로 한글 폰트임에도 로딩이 가볍습니다.
- `--font-satoshi` / `--font-inter`가 모두 `--font-pretendard`를 가리키게 했습니다.
  기존 변수 이름을 그대로 둔 이유는 **테마 패널의 폰트 선택 로직을 건드리지 않기 위해서**입니다.
- 제목/본문을 같은 서체로 두고 위계는 **굵기·크기·자간**으로만 만듭니다. (DESIGN 1.md의 원칙과 동일)
- 폰트 CDN이 막힌 환경에서도 `Pretendard`(로컬) → `Apple SD Gothic Neo` → `Malgun Gothic` 순으로 폴백합니다.

**한글 조판 보정** — 영문 기준 값을 그대로 쓰면 한글이 깨집니다:

| 항목 | 영문 기준 | 한글 보정 | 이유 |
|---|---|---|---|
| 디스플레이 행간 | 1.0 | **1.18** | 한글은 받침 때문에 글자 높이가 커서 1.0이면 줄이 붙어 보임 |
| 디스플레이 자간 | -0.025em | **-0.035em** | Pretendard는 기본 자간이 넉넉해 큰 크기에서 더 조여야 함 |
| 제목 굵기 | 500 | **600** | 한글 500은 영문 500보다 가늘게 읽힘 |
| 줄바꿈 | 기본 | **`word-break: keep-all`** | 한글 단어가 중간에서 잘리는 것 방지 |
| 히어로 본문 폭 | 52ch | **44ch** | 한글은 글자당 정보량이 커서 같은 ch 수가 더 길게 느껴짐 |

## B-2. 3단계 "눈 높이기" — 절제형 모션

글은 애니메이션을 권하지만, **과한 연출이 오히려 템플릿 티를 냅니다.**
Dub·Linear가 실제로 쓰는 수준인 "페이드 + 8px 상승 + 순차 지연"만 적용했습니다.

| 요소 | 동작 |
|---|---|
| 스크롤 리빌 | `IntersectionObserver`로 뷰포트 진입 시 `opacity 0→1`, `translateY(8px)→0`. 0.55s |
| 순차 지연 | 같은 부모를 공유하는 형제끼리 55ms 간격. **최대 6칸까지만** — 더 늘리면 느리게 느껴짐 |
| 탭 전환 | 뷰 자체는 페이드만. 상승 모션은 자식이 담당해 이중으로 움직이지 않음 |
| 탭 전환 시 리빌 | 새 뷰의 리빌을 초기화 후 재관찰. 전환할 때마다 콘텐츠가 다시 올라옴 |
| 스크롤 진행 바 | 상단바 하단 헤어라인 위 2px 액센트가 차오름 |
| 장르 그래프 | 화면 진입 시 각 세그먼트가 0에서 `--seg-w`까지 0.45s 확장 |
| 문서 팝업 | 슬라이드 번호 배지(`1 / 3`) 추가, 진행 바와 크로스페이드 |
| 사이드 내비 | 활성 항목이 2px 안쪽으로 미세하게 들어감 |

**하지 않은 것** (의도적): 패럴랙스, 숫자 카운트업, 스티키 스크롤 씬, 마그네틱 커서, 타이핑 효과.
전부 "AI가 만든 랜딩페이지" 인상을 강화하는 요소들입니다.

**접근성**: `prefers-reduced-motion: reduce`이면 리빌·그래프 애니메이션이 전부 꺼지고 즉시 최종 상태로 표시됩니다.

## B-3. 3단계 검증

Chromium 헤드리스, 모션 정상/최소화 × 데스크톱 1440 / iPhone 12:

- 히어로 리빌 4개 즉시 노출, 바닥까지 스크롤 시 미노출 요소 0개
- 탭 전환(게임 → 문서) 후에도 리빌 재발화 확인, 미노출 0개
- 스크롤 진행 바 100% 도달, 장르 세그먼트 실제 폭 288.66px 렌더
- 문서 슬라이드 번호 `1 / 3` 출력, 자동 순환 동작
- `prefers-reduced-motion` 환경에서 동일하게 전 요소 노출 (모션만 제거)
- 가로 오버플로 0px, JS 에러 0건

**한 가지 미검증 항목**: 이 검증 환경은 외부 네트워크가 막혀 있어 **Pretendard CDN이 로드되지 않았습니다.**
폴백 스택이 정상 동작하는 것은 확인했으나, 실제 Pretendard 렌더링과 위 한글 조판 보정값의 최종 인상은
**사용자 브라우저에서 직접 확인**이 필요합니다. 자간·행간이 어색하면 `.display` / `.h-lg`의
`letter-spacing`·`line-height`를 조정하시면 됩니다.

# 부록 C. 궤도 맵 (Radial Orbital Map) 이식

원본: 21st.dev `radial-orbital-timeline` (React + shadcn/ui + Tailwind + lucide-react)

## C-1. 왜 바닐라로 다시 썼는가

원본을 그대로 쓰려면 Next.js + Tailwind + shadcn + Radix + CVA + lucide-react가 필요합니다.
지금 프로젝트는 **빌드 없는 3파일 구조**이고 1~3단계 작업물이 모두 그 전제 위에 있습니다.
컴포넌트 하나 때문에 프로젝트 성격을 바꾸는 대신, 동작을 그대로 이식했습니다.

| 원본 의존성 | 대체 |
|---|---|
| Tailwind 유틸리티 클래스 | `style.css` 섹션 17, 기존 토큰 재사용 |
| shadcn `Card` / `Badge` / `Button` | `.orbit__panel` / `.opanel__badge` / `.opanel__chip` |
| lucide-react 아이콘 | 인라인 SVG 5종 (`currentColor` 사용 → 색 자동 추종) |
| React `useState` / `useEffect` | 클로저 변수 + `requestAnimationFrame` |

## C-2. 원본과 의도적으로 다르게 한 4가지

1. **`setInterval(50ms)` → `requestAnimationFrame` + 델타 시간**
   원본은 50ms마다 0.3도씩 더합니다. 탭이 백그라운드로 가도 계속 돌고, 프레임이 밀리면 속도가 느려집니다.
   rAF는 백그라운드에서 자동 정지하고, 델타 시간을 쓰므로 어떤 프레임레이트에서도 초당 6도로 일정합니다.

2. **화면 밖이면 루프 정지** — `IntersectionObserver`로 궤도가 뷰포트를 벗어나면 rAF를 취소합니다.
   `visibilitychange`도 함께 걸어 탭 전환 시에도 멈춥니다. 노트북 배터리에 직접 영향이 있습니다.

3. **커서가 올라가면 회전 정지** — 원본은 계속 돌아서 움직이는 표적을 눌러야 합니다.
   `@media (hover:hover)` 환경에서만 `mouseenter`/`focusin`에 회전을 멈춥니다. 터치 기기는 원래대로.

4. **상세 카드를 노드에 붙이지 않음** — 원본은 카드가 노드 바로 아래(`top-20`)에 따라다닙니다.
   좁은 화면에서 잘려나가고, 노드가 궤도 위쪽에 있으면 카드가 궤도를 덮습니다.
   - **넓은 화면(≥860px)**: 카드를 궤도 **오른쪽**에 고정, 선택한 노드는 0°(오른쪽)로 이동 → 시선이 좌→우로 이어짐
   - **좁은 화면**: 카드를 궤도 **아래 일반 흐름**에 배치, 선택한 노드는 90°(아래)로 이동
   - 두 모드 모두 세로 공간 계산이 필요 없어 어떤 높이에서도 잘리지 않습니다.

## C-3. 풀블리드 처리에서 만난 문제

이 밴드는 화면 전폭이어야 하는데, 좌측 사이드바(220px) 때문에 **부모의 중앙이 화면의 중앙이 아닙니다.**
흔히 쓰는 `width:100vw; margin-left:calc(50% - 50vw)`는 두 가지 이유로 실패합니다.

1. `100vw`는 스크롤바 폭을 포함해서 데스크톱에서 가로 스크롤이 생깁니다.
2. `50%`가 사이드바만큼 오른쪽으로 밀린 지점이라 밴드가 오른쪽으로 치우칩니다.

그래서 `app.js`의 `layoutBleed()`가 실제 좌표를 재서 인라인으로 넣습니다.
처음에는 자기 자신의 `getBoundingClientRect()`를 쓰려고 인라인 스타일을 지웠다 다시 넣었는데,
**리플로우 타이밍에 따라 `left`가 0으로 잡히는 경우**가 있어 (모션 최소화 설정에서 재현) 밴드가 400px 어긋났습니다.
지금은 **우리가 건드리지 않는 부모의 rect**를 재는 방식이라 항상 안정적입니다.

## C-4. 노드 데이터

`app.js` 상단 `ORBIT_DATA` 배열에서 수정합니다.

```js
{ id, tab, title, date, status, energy, related, content }
//  tab     : 클릭 시 이동할 탭 (intro | projects | skills | docs | games)
//  related : 함께 빛낼 노드 id 배열
//  energy  : 0~100, 게이지로 표시
//  status  : completed | in-progress | pending
```

현재는 5개 목차와 1:1로 묶여 있어 **궤도 맵이 곧 메인 내비게이션** 역할을 합니다.
카드의 "보러 가기" 버튼과 연결 칩이 실제 탭 전환·노드 전환으로 이어집니다.

## C-5. 접근성

- 노드는 `<button>` — Tab으로 이동, Enter/Space로 열림, `aria-expanded` 반영
- 포커스 시 회전 정지 + 흰색 포커스 링
- Esc로 닫힘
- `prefers-reduced-motion`이면 자동 회전·펄스·핑 애니메이션 전부 정지 (선택·이동은 그대로 동작)

## C-6. 검증

Chromium 헤드리스, 모션 정상/최소화 × 1440 / iPhone 12 / 375px:

- 노드 5개 렌더, 자동 회전 동작 (모션 최소화 시 정지 확인)
- 노드 클릭 → 패널 열림, 연결 노드 3개 하이라이트, 게이지 70% 반영
- 연결 칩 클릭 → 다른 노드로 전환 (기술 → 소개)
- "보러 가기" → 해당 탭으로 이동 확인
- Esc → 패널 닫힘
- 풀블리드 정확도: left=0, width=뷰포트 폭과 일치 (4개 환경 전부)
- 가로 오버플로 0px, JS 에러 0건

# 부록 D. 이력서 탭 (v0.5)

여섯 번째 탭. 상단 우측 "이력서" 버튼도 이 탭으로 연결되도록 바꿨습니다.

## D-1. 4개 문단 구성

| 번호 | 문단 | 형식 |
|---|---|---|
| 01 | 기획자를 선택한 계기 | 로그라인 인용 블록 + 2단 본문 |
| 02 | 강점과 기획자의 연결 | 카드 3장, 각 카드가 위아래로 분리 |
| 03 | 경험 — 문제 해결 과정 | 케이스 2개, 세로 스테퍼 |
| 04 | 기획자가 된다면 | 6개월 / 1~2년 / 3년 이후 + 마무리 블록 |

**02에서 카드를 위아래로 가른 이유**: 요구사항이 "강점 → 기획자와의 연관성"이었습니다.
강점만 나열하면 흔한 이력서가 되고, 연결이 본문 속에 묻히면 안 읽힙니다.
점선 위는 강점, 아래는 "기획자로서" 라벨을 단 사용처 — 연결 자체를 레이아웃으로 만들었습니다.

## D-2. 경험 파트 — 전개 틀 전환

`app.js` 상단 **한 줄**로 두 케이스의 단계 표기가 함께 바뀝니다.

```js
var RESUME_FRAMEWORK = 'star';   // 'star' | 'sahb'
```

| 값 | 이름 | 단계 |
|---|---|---|
| `star` | STAR | **S** 상황 · **T** 과제·문제 정의 · **A** 행동·방법 제시 · **R** 결과 · **L** 배움·얻은 것 |
| `sahb` | 상행결배 | **상** 상황 · **행** 행동 · **결** 결과 · **배** 배움 |

- 단계 원 안에 번호(1~5) 대신 **프레임워크 글자**가 들어갑니다. 어떤 틀을 쓰는지 한눈에 보입니다.
- 라벨은 `상황 SITUATION` 처럼 한글 + 영문 병기.
- 섹션 제목 오른쪽에 현재 틀을 표시하는 배지가 붙습니다.
- 상행결배로 바꾸면 `task` 단계가 **숨겨지고**, 마지막 단계에 `.step--last` 가 다시 부여되어
  세로 연결선이 정확히 거기서 끊깁니다. (단계 수가 달라져도 선이 허공에 뜨지 않습니다.)
- HTML은 5단계를 모두 갖고 있으므로, 틀을 바꿔도 작성해둔 내용은 사라지지 않고 숨겨질 뿐입니다.

케이스별로 다른 틀을 쓰고 싶으면 해당 `<article class="case">`에 `data-framework="sahb"`를 붙이면
그 케이스만 개별 적용됩니다. 다만 **두 케이스를 같은 틀로 쓰는 쪽을 권합니다** —
틀이 같아야 읽는 사람이 두 번째 케이스부터 내용에만 집중합니다.

## D-3. 아직 정하지 않은 것

- **PDF 내려받기 버튼**: 자리만 잡혀 있고 `href="#"` 입니다. 실제 파일을 연결하거나, 안 쓸 경우 삭제하세요.
- 연락 CTA의 `mailto:TODO@example.com` 도 교체 대상입니다.

## D-4. 검증

Chromium 헤드리스, 데스크톱 1440 / iPhone 12:

- STAR: 배지 `STAR`, 두 케이스 모두 5단계(S/T/A/R/L) 정상 표기

# 부록 E. 문서 서류철 (File Deck) — v0.6

문서 탭의 카드 그리드를 서류철 스택으로 완전히 대체했습니다.
물리적 서류철에서 폴더를 꺼내 보는 은유이며, 궤도 맵과 마찬가지로 풀블리드 밴드로 처리했습니다.

## E-1. 확정한 방향

| 항목 | 결정 |
|---|---|
| 톤 | **문서 탭 전용 세계관** — 크림색 종이 + 모노스페이스 + 검정 열람 카드 |
| 폴더 내용 | **이미지 + 텍스트 병행** — 좌측 슬라이드, 우측 메타·요약·열람 링크 |
| 기존 그리드 | **완전 대체** — 같은 정보를 두 번 보여주지 않음 |
| 동작 | 선택한 폴더 위쪽이 밀려나고 그 자리에 열람 카드가 열림 |

궤도 맵이 다크 밴드라면 서류철은 그 반대 온도의 밴드입니다.
페이지 전체가 흰 캔버스인 가운데 두 구간만 각자의 세계를 갖습니다.

## E-2. 레이아웃 규칙 3가지

1. **폴더의 가로 폭은 절대 변하지 않는다.**
   `inset = (N-1-k) * INSET` 로 인덱스에만 의존합니다. 선택해도 폭이 출렁이지 않습니다.
   (선택한 폴더를 넓히는 방식도 시도했지만, 고를 때마다 스택 전체가 요동쳐서 버렸습니다.)

2. **선택하면 위쪽 폴더가 사라지고, 남은 폴더가 그만큼 위로 올라온다.**
   `top = (k - sel) * STEP`. 아래쪽 폴더들의 상대 위치는 유지됩니다.

3. **스택이 줄어드는 만큼 열람 카드가 위에서 자란다.**
   두 변화가 상쇄되어 섹션 전체 높이가 크게 요동치지 않습니다.
   카드는 `grid-template-rows: 0fr → 1fr` 로 높이를 부드럽게 전환합니다.

## E-3. 구현 중 잡은 버그 2개

**`<button>` 의 세로 가운데 정렬** — 폴더를 `<button>` 으로 만들었더니 색인 띠가 폴더 한가운데
(위에서 79px 아래)에 찍혔습니다. 브라우저가 버튼 내용을 세로 가운데로 맞추기 때문이고,
`display:block` 으로는 풀리지 않습니다. `display:flex; flex-direction:column; justify-content:flex-start`
로 강제해서 해결했습니다. 폴더는 키가 크고 색인 띠는 반드시 맨 위에 있어야 하는 구조라 치명적이었습니다.

**좁은 화면에서 라벨 삐져나감** — 라벨 위치를 `left: 70%` 같은 값으로 잡았더니
모바일의 좁은 폴더에서 글자가 오른쪽 밖으로 나갔습니다.
`left` 를 라벨의 **중심**으로 재정의하고(`translate(-50%,-50%)`) `max-width` 와 말줄임을 걸었습니다.

## E-4. 풀블리드 유틸 일반화

궤도 맵 전용이던 `layoutBleed()` 를 `layoutBleedAll()` 로 일반화했습니다
(`bleedSelectors = ['#orbital', '#filedeck']`).

**숨겨진 탭 문제**: 서류철은 문서 탭 안에 있어서, 다른 탭이 활성인 동안에는
`getBoundingClientRect()` 가 전부 0 입니다. 그 상태로 계산하면 밴드가 어긋납니다.
그래서 `setView()` 가 탭을 연 **다음 프레임**에 `layoutBleedAll()` 과 `layoutDeck()` 을 다시 부릅니다.
`offsetWidth === 0` 인 요소는 계산에서 건너뜁니다.

## E-5. 데이터 편집

`app.js` 상단 `FILES` 배열에서 수정합니다.

```js
{ code, label, kind, date, title, summary, tags, slides, url }
//  code   : 폴더 위 검정 배지 (빈 문자열이면 배지 없음)
//  label  : 폴더 색인 띠에 찍히는 짧은 이름
//  slides : 미리보기 이미지 경로 배열 (비우면 자리표시자)
//  url    : 실제 문서 링크
```

라벨과 배지의 가로 위치는 `FD_TAB_X` / `FD_CODE_X` 배열에서 조정합니다.
손으로 꽂은 색인표처럼 일부러 어긋나게 배치했습니다.
파일 개수를 바꾸면 서랍 바닥의 `PORTFOLIO / NN FILES` 표기도 자동으로 따라갑니다.

## E-6. 접근성

- 폴더는 `<button>` — Tab 이동, Enter/Space로 열기, `aria-expanded` 반영
- 스택에 포커스가 있을 때 **↑ ↓** 로 파일 사이 이동
- Esc로 닫기 (궤도 맵·테마 패널과 동일)
- 밀려난 폴더는 `tabindex="-1"` + `pointer-events:none` 으로 탭 순서에서 제외
- `prefers-reduced-motion` 이면 전환·슬라이드 순환·커서 깜빡임 모두 정지

## E-7. 모션 다듬기 (v0.6.1)

첫 구현은 전환이 한 번에 일어나 뻣뻣했습니다. 세 가지를 고쳤습니다.

**1) `top`·`height` 애니메이션을 `transform` 하나로 교체**

원래는 `top`, `left`, `right`, `height`를 모두 전환 대상으로 걸었습니다.
이 속성들은 바뀔 때마다 브라우저가 레이아웃을 다시 계산해서 프레임이 끊깁니다.

지금은 `top`·`height`를 **닫힌 상태 기준으로 한 번만** 정하고 그대로 두고,
이동은 `transform: translateY()` 하나로만 합니다. 합성 단계에서만 처리되어 매끄럽습니다.

이게 가능한 이유: 폴더 높이를 `(N-1-k) * STEP + LAST`로 고정하면
**닫힌 상태에서 모든 폴더의 아랫변이 서랍 바닥의 윗변과 정확히 일치**합니다.
그래서 스택 전체가 `shift`만큼 올라가도 폴더 아랫변과 바닥이 계속 붙어 있습니다.
(폴더가 바닥 뒤로 지나가므로 `.fd-base`에 `z-index:20`을 줬습니다.)

**2) 순서를 어긋나게 — 종이가 한 장씩 들리도록**

| 상황 | 지연 |
|---|---|
| 열 때 (밀려나는 폴더) | 선택한 폴더 **바로 위부터** 48ms 간격, 최대 4칸 |
| 닫을 때 (돌아오는 폴더) | **맨 위부터** 30ms 간격, 최대 5칸 |
| 열 때 (남는 폴더) | 지연 없음 — 서랍 바닥과 함께 움직여야 하므로 |

밀려나는 폴더는 위로 34px 빠지면서 `rotate(±0.7deg)` 기울고 `scale(.985)`로 살짝 줄어듭니다.
기울기 방향을 인덱스 홀짝으로 번갈아 줘서 손으로 들어낸 것처럼 흐트러집니다.

**3) 등장 리듬**

- 선택된 폴더의 색인 띠에 `fdPull` 반동 (0 → -7px → 0). 부모의 `transform`과 겹치지 않도록 **자식**에 겁니다.
- 카드 내부 7개 블록이 100ms부터 40ms 간격으로 차례로 올라옵니다 — 서류를 훑는 순서대로.
- 다른 폴더로 갈아탈 때도 이 리듬이 다시 돕니다. 클래스를 뗐다 붙이는 것만으로는
  애니메이션이 재시작되지 않아 사이에 `void offsetWidth`로 리플로우를 한 번 강제합니다.
- 커서를 올리면 색인 띠만 3px 들립니다 — 꺼낼 수 있다는 신호.

이징은 `cubic-bezier(.16,.84,.28,1)` 하나로 통일했습니다. 빠르게 출발해 조용히 멎습니다.
지속시간은 자리 이동 0.52s, 사라짐 0.34s.

# 부록 F. 소개 — "이 포트폴리오의 페이지" 안내 (v0.7.1)

기존 "이 페이지의 구성" 4칸(소개·프로젝트·기술·게임)을 **다른 페이지로 가는 안내 5칸**으로 바꿨습니다.

## F-1. 무엇을 고쳤나

- **소개 칸 제거** — 소개는 현재 페이지 자신이라 자기 자신으로 가는 링크는 안내로서 의미가 없습니다.
- **문서·이력서 칸 추가** — 6개 탭 중 소개를 뺀 5개(프로젝트·기술·문서·게임·이력서)를 모두 담았습니다.
- **각 칸을 실제 링크로** — `<article>` → `<a href="#tab">`. 마우스 클릭뿐 아니라 **Tab 포커스 + Enter**로도 열립니다.
- **"페이지 열기 →" 안내** — 평소엔 흐리게, 호버·포커스 시 액센트 색으로 밀려나와 링크임을 알립니다.
- **설명 자리 명시** — 제목(`한 줄 소개`)과 본문(`짧고 명료하게 1~2줄`)을 나눠, 각 페이지를 텍스트로 요약하는 자리를 분명히 했습니다.

## F-2. 결정 사항

- 5번째(이력서) 카드는 `grid-column:1/-1`로 아래 한 줄을 채웁니다. 2+2+1 격자에서 홀로 남는 반쪽 칸을 없앴습니다.
- 액센트는 컴포넌트당 1색 규칙에 따라 프로젝트=탠저린, 기술=라벤더, 문서=블루, 게임=그린, 이력서=딥사파이어.
  딥사파이어를 5번째로 추가(`[data-accent="sapphire"]`)했는데, 작은 점·라벨 액센트라 "주 액션 색"의 대면적 사용 금지 규칙과 충돌하지 않습니다.

## F-3. 편집 도구 연동 수정

링크 카드가 되면서 **편집 모드에서 카드 안 글자를 클릭하면 편집 대신 페이지 이동**이 되는 문제가 생겼습니다.
`edit-mode.js`에 캡처 단계 클릭 처리를 넣어, 편집 중(`[contenteditable]` 안 클릭)이면
이동을 막고(`preventDefault`+`stopPropagation`) 커서만 들어가게 했습니다.
상단 탭·버튼은 편집 대상이 아니므로 단일 클릭 이동이 그대로 유지됩니다.
